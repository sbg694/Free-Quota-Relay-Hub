# 04 · 风险、合规与安全

> 这一页不是免责声明，是**决策约束**：任何功能上线前先过一遍这张清单。合规问题一旦触发，代价远大于省下的那点额度钱。

## 1. 合规红线（不做，也不做成"可配置开关"）

| 红线 | 为什么 | 典型误踩方式 |
| --- | --- | --- |
| 批量注册账号薅新用户额度 | 违反几乎所有平台 ToS，涉嫌欺诈；触发风控会连带封设备/IP | 接码平台、虚拟号、自动化注册脚本 |
| 多账号轮换规避单账号限额 | 明确写在多数 ToS 的禁止条款里 | "我有 5 个 Google 账号所以有 5 份免费额度" |
| 转售 / 二次分发额度 | 中转站与官方条款普遍禁止转售；金额大时可能触及无证经营 | 把池子包装成"公益站"对外发 key |
| 抓取网页 / 逆向 Cookie 当 API | 违反 ToS + 可能违反《计算机信息系统安全保护条例》类规定 | 用浏览器插件导出 Cookie 后灌进池子 |
| 用免费额度做违法内容生成 | 责任在你，且平台会追责到账号 | 无内容审核的公开入口 |

**允许的灰区与不允许的灰区要分清**：

- ✅ 你实名注册的官方账号，其**官方公布的免费层**，按官方限额用 → 正常使用。
- ✅ 在第三方中转站**合法领取/购买**的额度，按其条款使用 → 正常使用。
- 🟡 把多个**你有权使用**的 key 放进一个池子做**负载均衡**（不是规避单账号限额）→ 看具体平台条款，多数平台对"同一主体多 key"是默许的，但"多账号"不是。
- ❌ 上面表格里的任何一条。

> 建议：接入每个来源前，在 自建的《来源条款清单》文件（不随仓库发布） 里填一栏「条款约束」，把原文关键句摘出来存档。出现争议时这是你唯一的凭据。

## 2. 第三方中转站的运营风险

| 风险 | 表现 | 缓解 |
| --- | --- | --- |
| **跑路** | 充值后突然停服、群解散 | 只充值小额；优先用"按量付费"而非大额预付；保留支付凭证 |
| **降智/换渠道** | 同一模型名，实际路由到便宜小模型 | 定期用固定 prompt 做一致性抽检；记录 `upstream_model` |
| **日志留存** | 对话内容被存储、被人工查看 | 敏感内容不进第三方；优先官方直连 |
| **key 二次倒卖** | 你的 key 被上游拿去转卖 | 只用自己的 key，别把 key 交给"代管"服务 |
| **计费不透明** | 倍率偷偷调整 | 记账与实际到账对账，异常立刻停用 |
| **连带封禁** | 上游账号被封，你的额度清零 | 分散来源，单来源占比 < 50% |

## 3. 技术风险

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 免费额度**随时变更** | 官方免费层是最容易被砍的东西（限额、模型、地区限制） | 配置化，不硬编码；来源失效要能一键停用 |
| 限流模型不公开 | 429 触发条件不透明 | 保守设置 RPM/并发；指数退避；记录 429 率 |
| 流式断流 | 上游中途断，客户端卡死 | 心跳 + 超时 + 补 `[DONE]` |
| token 计数偏差 | 各家 tokenizer 不同 | `estimated` 标记；关键对账以账单为准 |
| 模型名漂移 | 上游改模型 ID | 别名表 + 启动时探测 `/models` |
| 单点 | 网关自己挂了就全挂 | 本地进程守护（NSSM/systemd）；健康检查 |

## 4. 密钥安全（本项目最容易出事的地方）

1. **不落明文**：`keys.secret_enc` 用 AES-256-GCM，主密钥来自环境变量或系统凭据管理器，**不进仓库**。
2. **不进日志**：日志里 key 一律显示前 6 位 + `****`；`request_logs` 只存 `key_id`。
3. **不出口**：管理接口默认只监听 127.0.0.1；远程访问走隧道。
4. **最小权限**：每个上游 key 只开必要的模型权限（如果平台支持）。
5. **可撤销**：key 台账记录来源与获取日期，泄漏时能立刻定位、逐个吊销。
6. **`data/` 目录加 `.gitignore`**，即使误操作也不进版本库。

## 5. 数据与隐私

- 请求内容默认**不落盘**（只存指标）；需要排障时开启"样本模式"，只存 `prompt_hash` + 前 50 字，且 7 天自动清理。
- 如果你把网关开给家人/同事用，等于你成了"数据处理者"：应在 README 里写明数据去向（会经过哪些第三方）。
- 不上传任何 key、日志到第三方分析服务。

## 6. 质量与运营

- **来源分层**：把来源分为 `基石`（官方、稳定、有 SLA）、`补充`（中转站）、`实验`（活动额度），路由器按层给权重，避免"活动额度把主线路打挂"。
- **额度到期台账**：免费额度多数有有效期，账本里加 `expires_at` 列 + 到期前 3 天提醒，否则"薅到的额度一次没用就过期"。
- **对账制度**：每周一次，把本地账本与各平台余额对一次，偏差 > 10% 就查。
